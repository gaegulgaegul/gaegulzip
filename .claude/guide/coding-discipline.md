# Coding Discipline Guide

> 모든 개발 에이전트(node-developer, flutter-developer, react-developer)가 **구현 시점**에 따르는 판단 규칙.
> Karpathy 4원칙 + 멀티에이전트 환경 적용.

## 1. Surface Assumptions (가정 표면화)

**구현 전 반드시 수행:**

- brief.md / design-spec.md에서 모호한 부분이 있으면 **가정하지 말고 질문**
- 여러 해석이 가능하면 선택지를 제시: "A와 B 두 가지 해석이 가능한데, 어느 쪽인가요?"
- CTO가 없는 단독 작업이면 사용자에게 직접 질문

**Anti-pattern:**
```
❌ "아마 이렇게 하면 될 것 같다" → 자의적 해석으로 구현
✅ "이 API의 에러 응답 형식이 brief에 없습니다. { error: string } 형태로 진행할까요?" → 확인 후 구현
```

## 2. Simplicity First (최소 코드)

**자가 검증 기준:**

- "시니어 엔지니어가 이 코드를 보고 과하다고 할까?" → Yes면 단순화
- 200줄을 50줄로 줄일 수 있으면 줄일 것
- 단일 사용 추상화 금지 (3번 이상 쓰이지 않으면 인라인)
- 불가능한 시나리오의 에러 핸들링 금지
- 요청되지 않은 기능, 유연성, 설정 가능성 추가 금지

**Anti-pattern:**
```
❌ 할인 계산 하나에 Strategy 패턴 + Abstract Base Class + Config Dataclass
✅ 단일 함수로 구현. 할인 유형이 실제로 3개 이상 생기면 그때 패턴 도입
```

## 3. Surgical Changes (외과적 변경)

**변경 범위 규칙:**

- 요청과 직접 관련된 코드만 변경
- 인접 코드의 주석, 포맷팅, 네이밍 "개선" 금지
- 기존 코드 스타일과 다르더라도 맞출 것
- 기존 dead code 발견 시 언급만 하고 삭제하지 말 것

**자기 변경으로 생긴 고아 정리:**

- 자기 변경으로 unused 된 import, 변수, 함수만 정리
- 기존에 이미 unused였던 코드는 건드리지 않음

**멀티에이전트 특화 규칙:**

- work-plan.md의 "Files (생성/수정 허용)" 열에 명시된 파일만 수정
- "Files (수정 금지)" 열의 파일은 절대 수정 금지
- 다른 에이전트가 작업 중인 모듈 코드 건드리지 않음

**검증:** "모든 변경 라인이 요청에 직접 연결되는가?"

## 4. Goal-Driven Execution (검증 가능한 목표)

**모든 작업을 검증 가능한 목표로 변환:**

| 모호한 요청 | 검증 가능한 목표 |
|------------|----------------|
| "밸리데이션 추가" | "잘못된 입력에 대한 테스트 작성 → 테스트 통과시키기" |
| "버그 수정" | "버그 재현 테스트 작성 → 테스트 통과시키기" |
| "리팩토링" | "테스트 통과 확인 → 구조 변경 → 테스트 재확인" |
| "성능 개선" | "현재 응답 시간 측정 → 개선 → 재측정으로 검증" |

**스텝별 검증 체크포인트:**

```
1. [구현 스텝] → verify: [검증 명령어]
2. [구현 스텝] → verify: [검증 명령어]
```

**플랫폼별 검증 명령어:**

| 플랫폼 | 중간 검증 | 최종 검증 |
|--------|---------|---------|
| Server | `pnpm test -- [feature]` | `pnpm test && pnpm build` |
| Mobile | `flutter analyze` | `melos analyze` |
| Web | `pnpm build` + `pnpm lint` | `pnpm build && pnpm test:e2e` |

## 적용 시점

이 규칙은 **Do 단계 (구현)** 에서 적용됩니다:

```
Plan → Design → [Do: 이 규칙 적용] → Check → Act → Report
                  ↑
          coding-discipline.md
```

각 개발 에이전트는 구현 시작 전 이 가이드를 읽고 준수합니다.
