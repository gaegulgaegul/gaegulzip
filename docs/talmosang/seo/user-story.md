# 사용자 스토리: SEO 최적화

## 개요

탈모상은 바이럴 확산을 핵심 성장 전략으로 삼는 서비스다. 현재 기본적인 메타태그는 존재하지만, 검색엔진이 서비스를 제대로 색인하지 못하고, 카카오톡/X(트위터)/인스타그램 등 소셜 미디어에서 공유 시 링크 미리보기가 빈약하다. SEO를 강화하여 검색 유입을 확보하고, 소셜 공유 시 매력적인 미리보기가 표시되도록 하여 바이럴 확산 효과를 극대화한다.

---

## 사용자 스토리

### US-1: 검색엔진에서 탈모상 발견
- **As a** 탈모에 관심 있는 잠재 사용자
- **I want to** "탈모 테스트", "AI 두피 분석", "탈모 확률 검사" 등 관련 키워드로 검색했을 때 탈모상이 상위에 노출되기를
- **So that** 서비스를 유기적으로 발견하고 방문할 수 있다

### US-2: 소셜 공유 시 매력적인 미리보기 표시
- **As a** 탈모상 결과를 카카오톡/X/인스타그램에 공유하는 사용자
- **I want to** 공유한 링크에 탈모상 제목, 설명, 썸네일 이미지가 풍부하게 표시되기를
- **So that** 받는 사람이 링크를 클릭하고 싶은 호기심을 느낄 수 있다

### US-3: 검색엔진 크롤링 허용 범위 명확화
- **As a** 검색엔진 크롤러
- **I want to** 탈모상에서 크롤링 가능한 페이지와 불가능한 페이지를 즉시 파악할 수 있기를
- **So that** 서비스 전체 구조를 효율적으로 색인할 수 있다

### US-4: 사이트 구조 전달
- **As a** 검색엔진
- **I want to** 탈모상의 모든 페이지 목록과 각 페이지의 중요도를 알 수 있기를
- **So that** 누락 없이 정확하게 색인할 수 있다

### US-5: 서비스 내용 의미론적 이해
- **As a** 검색엔진
- **I want to** 탈모상이 어떤 서비스(웹 애플리케이션, 엔터테인먼트 도구)인지 구조화된 데이터로 확인할 수 있기를
- **So that** 검색 결과에 리치 스니펫(rich snippet)이나 적절한 카테고리로 노출할 수 있다

### US-6: 개인정보처리방침 페이지의 독립적 색인
- **As a** 법적 정보를 찾는 사용자 또는 검색엔진
- **I want to** 개인정보처리방침 페이지가 올바른 제목과 설명으로 독립적으로 색인되기를
- **So that** 서비스의 신뢰성을 확인할 수 있다

## 사용자 시나리오

### 시나리오 1: 검색을 통한 신규 유입 (정상 플로우)

1. 사용자가 포털 사이트(네이버, 구글)에서 "탈모 테스트 AI"를 검색한다
2. 검색 결과에 탈모상이 표시된다
   - 제목: "탈모상 - 내가 탈모가 될 상인가?"
   - 설명: "AI 관상가가 그대의 모발 운명을 점지하리라. 사진 하나로 탈모 확률, 모발 나이, 닮은 유명인을 알아보세요."
3. 사용자가 검색 결과를 클릭하여 탈모상에 접속한다
4. 결과: 검색 유입을 통한 신규 사용자 획득

### 시나리오 2: 카카오톡 링크 공유 (정상 플로우)

1. 사용자 A가 분석 결과를 확인하고 "공유하기"를 누른다
2. 사용자 A가 카카오톡으로 링크를 공유한다
3. 사용자 B가 카카오톡에서 공유된 링크를 본다
4. 링크 미리보기에 다음이 표시된다
   - 썸네일 이미지: 탈모상 브랜드 이미지 (캐릭터 포함)
   - 제목: "탈모상 - 내가 탈모가 될 상인가?"
   - 설명: 서비스 소개 문구
5. 사용자 B가 호기심을 느끼고 링크를 클릭한다
6. 결과: 소셜 공유를 통한 바이럴 확산

### 시나리오 3: X(트위터) 공유

1. 사용자가 X에 탈모상 링크를 게시한다
2. 트윗에 카드 형식(큰 이미지 포함)의 미리보기가 표시된다
   - 큰 이미지 썸네일
   - 제목과 설명
3. 타임라인에서 시각적으로 눈에 띄는 형태로 노출된다
4. 결과: 이미지 중심의 소셜 카드로 클릭률 향상

### 시나리오 4: 검색엔진 봇의 사이트 탐색

1. 구글봇이 탈모상을 처음 크롤링한다
2. robots.txt를 확인하여 크롤링 허용 범위를 파악한다
   - 허용: 메인 페이지, 개인정보처리방침 페이지
   - 차단: API 라우트, 내부 관리 경로 등
3. sitemap.xml을 확인하여 탈모상의 모든 페이지 목록을 수집한다
   - 메인 페이지 (/)
   - 개인정보처리방침 (/privacy)
4. 각 페이지를 방문하여 메타데이터와 구조화 데이터를 읽는다
5. 결과: 검색엔진이 누락 없이 탈모상 전체를 색인

### 시나리오 5: 검색 결과의 리치 스니펫 표시

1. 구글이 탈모상의 JSON-LD 구조화 데이터를 파싱한다
2. 탈모상이 웹 애플리케이션(또는 엔터테인먼트 도구) 유형으로 인식된다
3. 검색 결과에서 일반 블루링크보다 풍부한 형태로 노출된다
4. 결과: 검색 결과에서 클릭률(CTR) 향상

## 인수 조건 (Acceptance Criteria)

### 검색엔진 색인

- [ ] /robots.txt 경로로 접근 시 크롤링 정책 파일이 응답된다
- [ ] /sitemap.xml 경로로 접근 시 사이트맵 파일이 응답된다
- [ ] sitemap.xml에 메인 페이지(/)와 개인정보처리방침 페이지(/privacy)가 포함된다
- [ ] API 라우트(/api/*)는 robots.txt에서 크롤링이 차단된다
- [ ] 각 페이지에 canonical URL이 명시된다

### 메타데이터

- [ ] 메인 페이지에 고유한 title, description, keywords가 설정된다
- [ ] 개인정보처리방침 페이지에 독립적인 title, description이 설정된다
- [ ] 모든 페이지에 metadataBase가 올바른 프로덕션 도메인으로 설정된다

### 소셜 공유 미리보기 (Open Graph)

- [ ] 메인 페이지에서 og:title, og:description, og:image, og:type이 설정된다
- [ ] og:image가 실제 접근 가능한 URL로 제공된다 (상대 경로 아님)
- [ ] og:image 크기는 소셜 플랫폼 권장 비율(1200x630)을 충족한다
- [ ] 카카오톡에서 링크를 공유했을 때 썸네일 이미지와 제목이 표시된다
- [ ] X(트위터)에서 twitter:card가 summary_large_image로 설정된다
- [ ] X에서 링크를 게시했을 때 큰 이미지 카드 형태로 표시된다

### 구조화 데이터 (JSON-LD)

- [ ] 메인 페이지에 JSON-LD 구조화 데이터가 포함된다
- [ ] 구조화 데이터에 서비스명, 설명, URL이 포함된다
- [ ] Google Rich Results Test에서 유효성 검사를 통과한다

## 엣지 케이스

- **OG 이미지 없음 (파일 누락)**: 이미지 URL이 유효하지 않으면 소셜 플랫폼은 이미지 없이 제목/설명만 표시 - 이미지 파일 존재 여부를 사전 검증해야 함
- **카카오톡 캐시**: 카카오톡은 링크 미리보기를 캐싱하므로 OG 이미지 변경 후 즉시 반영되지 않을 수 있다 - 운영 가이드에 캐시 초기화 방법 안내 필요
- **메인 페이지가 'use client'**: 클라이언트 컴포넌트인 page.tsx에서는 metadata export가 불가 - layout.tsx에서 메타데이터를 관리하거나 서버/클라이언트 분리 구조로 대응
- **robots.txt에서 분석 API 노출**: /api/analyze, /api/generate-image는 외부에서 직접 호출을 막기 위해 크롤링 차단 처리 필요
- **sitemap에 동적 결과 페이지 포함 여부**: 분석 결과는 서버에 저장되지 않으므로 고유 URL이 없음 - sitemap은 정적 페이지(/, /privacy)만 포함

---

## 비즈니스 규칙

- **OG 이미지는 정적 이미지로 충분**: 현재 결과는 서버에 저장되지 않아 사용자별 동적 OG 이미지가 불가능하다. 서비스 브랜드 이미지를 공통 OG 이미지로 사용한다
- **한국어 서비스임을 명시**: og:locale을 ko_KR로 설정하여 한국어 콘텐츠임을 검색엔진에 알린다
- **바이럴 유도 문구**: og:description은 클릭 욕구를 자극하는 문구를 사용한다 ("AI 관상가가 그대의 모발 운명을 점지하리라")
- **분석 결과 URL 공유 불가**: 결과가 서버에 저장되지 않으므로 공유 링크는 항상 메인 페이지(/) URL을 가리킨다. 결과 자체의 OG 태그는 해당 기능 범위 밖이다
- **API 라우트 보호**: 검색엔진이 API 엔드포인트를 색인하지 않도록 robots.txt에서 명시적으로 차단한다

## 필요한 데이터

| 데이터 | 타입 | 필수 | 설명 |
|--------|------|------|------|
| 사이트 기본 URL | String | ✅ | 프로덕션 도메인 (예: https://talmosang.vercel.app) |
| OG 이미지 | Image (1200x630) | ✅ | 소셜 공유 썸네일 이미지 |
| 서비스 제목 | String | ✅ | 검색/공유 시 표시되는 서비스명 |
| 서비스 설명 | String | ✅ | 검색 결과 및 공유 미리보기 설명 문구 |
| 검색 키워드 | Array<String> | ✅ | 탈모, AI 두피 분석, 탈모 테스트 등 |
| 페이지별 고유 제목 | String | ✅ | 각 페이지의 독립적인 title |
| 서비스 카테고리 | String | ✅ | 구조화 데이터에 사용할 서비스 유형 |
| 마지막 수정일 | Date | ❌ | sitemap의 lastmod 값 |

## 비기능 요구사항

- **성능**: sitemap.xml과 robots.txt는 빠르게 응답해야 하며, 검색엔진 크롤러의 불필요한 대기 시간이 없어야 한다
- **접근성**: 구조화 데이터는 화면 렌더링에 영향을 주지 않는 방식(script 태그 내 JSON-LD)으로 삽입한다
- **에러 처리**: sitemap.xml, robots.txt 접근 실패 시 500이 아닌 명확한 에러 페이지를 반환한다
- **유지보수성**: 새 페이지가 추가될 때 sitemap에 자동으로 포함되는 구조가 이상적이다
- **표준 준수**: Open Graph Protocol 표준과 Google 구조화 데이터 가이드라인을 준수한다
